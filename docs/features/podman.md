# Podman 容器

在面板的「Podman 容器」页面可以部署 Nginx 等 OCI 应用。应用启动镜像内的进程，使用宿主机的 Linux 内核。需要完整 Linux 环境、系统盘或虚拟硬件时，请使用 [LXC 或 KVM](./containers)。

## 准备宿主机

先在 CLICD 所在的 Linux 宿主机安装 Podman，并确认 CLICD 服务账号能运行它。默认用 root 运行面板时，可在宿主机执行 `sudo podman info` 检查。以 Debian 或 Ubuntu 为例，可用各自的软件仓库安装。

```bash
sudo apt install podman
sudo podman info
```

用管理员账号登录并打开「Podman 容器」。这里管理通过面板创建的应用容器。CLICD 默认以 root 账号调用本机 Podman，适用于管理员部署自己信任的镜像。LXC/KVM 的子用户、快照和备份由各自的管理页面处理。

## 部署应用

1. 点击「创建容器」，填写名称和包含仓库地址的 OCI 镜像，例如 `docker.io/library/nginx:alpine`。
2. 如需从宿主机访问应用，添加端口映射，选择 TCP 或 UDP。例如，映射宿主机端口 `8080` 到容器端口 `80`。端口发布后可在网络允许的情况下通过 `http://<宿主机地址>:8080` 访问 Nginx。
3. 按应用需要设置 CPU 和内存上限。可填写环境变量，每行一个 `KEY=value`。若要传递启动参数，使用 JSON 字符串数组，例如 `["nginx", "-g", "daemon off;"]`。它会替换镜像默认的 `CMD`。镜像定义了 `ENTRYPOINT` 时，这些值将作为它的参数，具体写法以镜像说明为准。
4. 如需持久化数据，每行填写一个容器内的绝对目录，例如 `/var/cache/nginx`。Podman 会为这些目录创建卷。

应用端口发布到宿主机的 IPv4 接口。填写宿主机端口时，需避开 CLICD 当前配置的 [NAT4 端口范围](./networking#nat4)，以免与 LXC/KVM 的转发规则冲突。需要限制访问范围时，在宿主机或上游防火墙配置规则。

## 查看应用状态

在「应用」中按名称或镜像搜索，或按运行状态筛选。可从列表启动、停止或重启容器，也可打开详情，在「概览」中查看 CPU 和内存上限、已发布端口和持久卷路径。运行中的容器还显示 CPU、内存、网络和磁盘 I/O。应用退出后，可查看退出码。

## 查看应用日志

详情中的「日志」显示应用写入标准输出和标准错误的内容。可开启「自动刷新」，或复制、下载当前显示的日志。应用启动后立即退出时，可结合退出码、日志和镜像说明检查启动参数。

## 管理本地镜像

「本地镜像」显示当前 CLICD 服务账号的 Podman 本地缓存。可以搜索镜像标签，或点击「拉取镜像」并输入完整的 OCI 镜像名提前拉取。点击已有标签旁的「使用镜像」可直接打开创建容器表单，复用本地缓存。

## 持久卷

Podman 卷在停止和重启期间保留数据。删除容器会一并删除其匿名卷。删除前请先备份需要保留的应用数据。
